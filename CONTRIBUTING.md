# Contributing

Thanks for your interest in `deepseek-v4-flash-offload`. This document covers how to
set up an environment, run the self-checks, and submit changes.

## Scope

This project is an **out-of-tree vLLM / vllm-ascend plugin** for serving
`DeepSeek-V4-Flash` on a **single Ascend 950PR**. Contributions that keep the
"no fork" property (no `site-packages` edits, everything through the vLLM plugin
entry point) are welcome.

Please note the current limitations before proposing large features:

- Single card only (TP=1, no expert parallelism).
- MTP / speculative-decoding layers are out of scope.

## Environment

The runtime self-checks need a real Ascend environment; they cannot run on a
plain CPU box or in generic CI.

| Component | Version / note |
|---|---|
| Hardware | Ascend 950PR, 128 GB HBM (single card) |
| Python | 3.12 |
| vLLM | 0.23.0 |
| vllm-ascend | 0.23.0 (950 variant, cp312 wheel) |
| CANN | matching the vllm-ascend 0.23.0 build |

Install the runtime dependencies (`torch`, `torch-npu`, `vllm`, `vllm-ascend`)
following your vendor's instructions — they are intentionally **not** declared in
`pyproject.toml`. Then install this plugin in editable mode:

```bash
pip install -e .
source /usr/local/Ascend/ascend-toolkit/set_env.sh   # adjust to your CANN install
```

Point `DSV4_MODEL` at your local checkpoint:

```bash
export DSV4_MODEL=/path/to/DeepSeek-V4-Flash
```

## Running the self-checks

Tests are plain scripts, run from the repository root:

```bash
python test_npu_ops.py        # operator correctness vs torch references
python test_offload.py        # ExpertBank host bank + NPU slot cache
python test_loader.py         # weight loader (synthetic + real checkpoint)
python test_model.py          # model_npu forward (tiny + real config)
python test_moe_align.py      # MoE numerical alignment (bf16 bit-exact / a4w4 tolerance)
python test_plugin_load.py    # load_weights tee + expert capture
python test_e2e_vllm.py       # real vLLM engine end-to-end
```

Two more scripts are micro-benchmarks rather than pass/fail tests:

```bash
python _bench_dequant.py      # FP4/FP8 dequantization throughput
python _bench_gmm.py          # grouped-GEMM vs per-expert loop
```

For an end-to-end serving check:

```bash
./serve.sh                    # or: PROFILE=a4w4 ./serve.sh
python accept.py              # HTTP acceptance benchmark
```

## Code style

- Match the surrounding code; there is no enforced formatter.
- Keep the module boundaries: `dsv4_plugin/` is the shipped plugin, while
  `npu_ops.py` / `offload.py` / `loader.py` / `model_npu.py` are top-level helper
  and reference modules that must stay importable from the repository root.
- Do not add new runtime dependencies to `pyproject.toml` — the empty
  `dependencies` list is deliberate.

## Regenerating diagrams

The README diagrams live in `docs/diagrams/` and are generated by
`docs/diagrams/animate.py`, which needs `cairosvg` and `Pillow` (no `ffmpeg`):

```bash
pip install cairosvg Pillow
python docs/diagrams/animate.py
```

The script writes its GIFs next to itself and uses a temporary directory for
frames, so it runs from any checkout location. Only the assets referenced by the
READMEs are committed — please do not commit intermediate PNG/HTML renders.

## Submitting changes

1. Open an issue describing the problem or feature first for non-trivial changes.
2. Keep pull requests focused; one logical change per PR.
3. Update `README.md` / `README_zh.md` and `DESIGN.md` when behaviour or measured
   numbers change, and add a note under `CHANGELOG.md` → `[Unreleased]`.
4. Describe how you validated the change (which self-checks ran, on what build).

CI runs a hardware-free subset (byte-compile + wheel-content check); the NPU
self-checks are expected to be run locally and reported in the PR description.
